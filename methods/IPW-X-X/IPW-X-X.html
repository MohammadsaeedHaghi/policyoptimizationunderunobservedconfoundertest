IPW

Calibrated Inverse-Propensity-Weighted value maximiser — the non-robust baseline (formerly srpo.multiarm.solve_direct_ipw_multiarm). This page states exactly the in-sample optimisation problem the two files in this folder solve: Capped/ipw_capped.py and Uncapped/ipw_uncapped.py.

One sentence. IPW learns the policy that maximises the calibrated Hájek/IPW value on the training sample — with no worst case, no Rosenbaum/Tan odds box and no Wasserstein covariate-balance ball — optionally subject to per-arm capacity.

1 · Inputs (all fixed before the optimiser runs)

The method does no statistical preprocessing; it consumes quantities prepared by common/:

symbolmeaningsource
\(x_i,\;T_i,\;Y_i\)covariates, observed arm, observed outcome of unit \(i=1,\dots,n\); arms \(k=0,\dots,K-1\)data
\(\hat w_i = 1/\hat P(T_i\mid x_i)\)nominal inverse weight, per-arm Hájek-normalised (\(\sum_{i:T_i=k}\hat w_i=n\)). Estimated from \((X,T)\) — never the true propensity.common.ipw_weights_from_data
\(\mathrm{cap}_k\)per-arm capacity (capped version only)caller

Note what is absent versus R-O and R-OW: there is no sensitivity level \(\Gamma\), no MSM box \([a_i,b_i]\), no distance matrix \(D\) and no Wasserstein radius \(\varepsilon_k\) — IPW drops the robustness entirely, so it has no Gamma, no c_eps/epsilon argument and no dual certificate.

2 · The decision: a policy on the (discretised) support

We learn \(\pi_k(x)\in[0,1]\) with \(\sum_k\pi_k(x)=1\). The discretize/mesh arguments fix where \(\pi\) is defined exactly as in R-O / R-OW: discretize=True snaps the covariates onto a mesh-level grid (common.support) and ties same-cell units to one policy value (so \(\pi\) is piecewise-constant in \(x\)); discretize=False uses the raw covariates (singleton support — degenerate on continuous \(x\)). The discretisation is still needed even though IPW has no robustness term: it is what pools units so the free-π LP is well-posed.

3 · The in-sample problem (the IPW value)

The calibrated IPW value of a policy \(\pi\) on the sample is \(V(\pi)=\frac1n\sum_i \hat w_i\,Y_i\,\pi_{T_i}(x_i)\): each unit contributes only through its observed arm \(T_i\), reweighted by its nominal inverse weight \(\hat w_i\). IPW simply maximises this value (no inner \(\min_W\) — there is no worst case):

\[ \boxed{\;\pi^\star \;=\; \arg\max_{\pi\in\Pi}\ \frac1n\sum_{i=1}^{n} \hat w_i\,Y_i\,\pi_{T_i}(x_i)\;} \]

over the feasible policy set

\[ \Pi:\quad \pi_k(x_i)\ge 0,\qquad \sum_{k}\pi_k(x_i)=1\ \ \forall i,\qquad \underbrace{\tfrac1n\sum_{i}\pi_k(x_i)\le\mathrm{cap}_k\ \ \forall k}_{\textbf{capped version only}}, \]

(plus the tie constraints). There is no uncertainty set: \(\hat w\) is taken at face value.

4 · How it is solved — a direct LP (no dualisation needed)

Unlike R-O and R-OW, IPW has no inner adversary (\(\min_W\)), so there is nothing to dualise — the problem of Section 3 is handed to the solver verbatim.

Step 1 (the objective is already linear). The calibrated IPW value

\[ V(\pi)\;=\;\frac1n\sum_{i=1}^{n} \hat w_i\,Y_i\,\pi_{T_i}(x_i) \]

is linear in the policy variables \(\pi_{k,i}=\pi_k(x_i)\): each \(\hat w_i\,Y_i\) is a fixed constant, multiplying the single decision variable \(\pi_{T_i}(x_i)\). No worst-case minimisation, no MSM box and no transport plan appear, so there are no auxiliary or dual variables to introduce.

Step 2 (maximise it directly under the policy constraints). We maximise \(V(\pi)\) directly subject only to the constraints that define a valid (capacity-limited) policy:

\[ \begin{aligned} &\textstyle\sum_{k}\pi_k(x_i)=1,\quad \pi_k(x_i)\ge 0\quad\forall i; &&\text{(per-unit simplex)}\\[2pt] &\pi \text{ tied on each cell}; &&\text{(per-cell tie)}\\[2pt] &\textstyle\frac1n\sum_i \pi_k(x_i)\le \mathrm{cap}_k\quad\forall k. &&\textbf{(capacity — capped only)} \end{aligned} \]

Step 3 (solve). The result is a plain LP in the single variable block \(\pi\), which is handed straight to Gurobi. Because there is no box (and no Wasserstein ball), this LP is exactly R-OW and R-O at \(\Gamma=1\): IPW \(=\) R-OW \(=\) R-O when \(\Gamma=1\).

How it is used. The solve returns the on-support policy \(\pi\) (a \(K\times n\) array); off-support deployment to new covariates is a separate step, done by Shapley/KNN extension (see extensions/).

5 · What is actually solved (plain LP)

Because there is no inner \(\min_W\) to dualise, the problem above is the LP the files build — a plain LP, linear in \(\pi\). The only variables are the policy values \(\pi_k(x_i)\); there are no dual multipliers (no \(\mu,\nu,\beta\) and no transport duals), so nothing is returned as a "dual certificate".

\[ \max_{\pi}\ \ \frac1n\sum_{i=1}^{n} \hat w_i\,Y_i\,\pi_{T_i}(x_i) \]

subject to

\[ \begin{aligned} &\textstyle\sum_k \pi_k(x_i)=1,\quad \pi_k(x_i)\in[0,1],\quad \pi \text{ tied on each cell}; &&\text{(valid policy)}\\[2pt] &\textstyle\frac1n\sum_i \pi_k(x_i)\le \mathrm{cap}_k\quad\forall k. &&\textbf{(capacity — capped only)} \end{aligned} \]
variablemeaning
\(\pi_k(x_i)\in[0,1]\)the policy on the (discretised) support — the only decision variable; columns sum to 1

Reproduced exactly from srpo.multiarm.solve_direct_ipw_multiarm — the same per-arm-normalised weights \(\hat w\) as the robust methods, so IPW coincides with R-O and R-OW at \(\Gamma=1\).

6 · Capped vs. Uncapped — the only difference

  • Capped/ipw_capped.py — adds \(\frac1n\sum_i\pi_k(x_i)\le\mathrm{cap}_k\) (requires cap).
  • Uncapped/ipw_uncapped.py — drops it (no cap argument); any arm may be assigned to any fraction.

7 · IPW vs R-O vs R-OW

Same value-maximisation, same discretisation and capacity — IPW simply drops the robustness entirely: no odds box (so no \(\Gamma\), no \([a_i,b_i]\), no \(\mu,\nu\)), and no Wasserstein covariate-balance ball (so no \(D\), no \(\varepsilon_k\), no transport \(\gamma,\theta\) duals). It optimises the nominal IPW value at face value rather than a worst case. At \(\Gamma=1\) the odds box of R-O / R-OW collapses to a point and the Wasserstein ball never binds, so IPW equals both R-O and R-OW; as \(\Gamma\) grows the robust methods hedge against unobserved confounding while IPW stays put.

Outputs: the optimal on-support policy \(\pi^\star\) (K×n), its realised per-arm usage, and the calibrated IPW objective — persisted per results/SAVING.md. There is no dual certificate (no robustness). Off-support deployment (extensions/) is a separate step.
