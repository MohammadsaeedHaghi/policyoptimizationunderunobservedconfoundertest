Direct-X-X

The naive factual-reward maximiser — Direct IPW with all weights pinned to one (formerly srpo.multiarm.solve_direct_opt_multiarm). This page states exactly the in-sample optimisation problem the two files in this folder solve: Capped/direct_x_x_capped.py and Uncapped/direct_x_x_uncapped.py.

One sentence. Direct-X-X learns the policy that maximises the raw observed factual reward on the training sample, with no inverse-propensity weighting and no confounding adjustment — it simply trusts the confounded data as-is. Optionally subject to per-arm capacity. It is the weakest baseline here; it equals IPW when all weights are 1.

1 · Inputs (all fixed before the optimiser runs)

The method does no statistical preprocessing; it consumes only the raw data:

symbolmeaningsource
\(x_i,\;T_i,\;Y_i\)covariates, observed arm, observed outcome of unit \(i=1,\dots,n\); arms \(k=0,\dots,K-1\)data
\(\hat w_i \equiv 1\)weights are pinned to one: no \(1/\hat P(T\mid x)\) reweighting at all. This method does not take an ips_weights argument.(none — internal constant)
\(\mathrm{cap}_k\)per-arm capacity (capped version only)caller

Note what is absent versus every other method here: there is no nominal weight \(\hat w_i\), no sensitivity level \(\Gamma\) and odds box \([a_i,b_i]\), no distance matrix \(D\) and no Wasserstein radius \(\varepsilon_k\). Direct-X-X drops all robustness and even the propensity correction, so it has no ips_weights/Gamma/c_eps/epsilon argument.

2 · The decision: a policy on the (discretised) support

We learn \(\pi_k(x)\in[0,1]\) with \(\sum_k\pi_k(x)=1\). The discretize/mesh arguments fix where \(\pi\) is defined exactly as in R-O / R-OW: discretize=True snaps the covariates onto a mesh-level grid (common.support) and ties same-cell units to one policy value (so \(\pi\) is piecewise-constant in \(x\)); discretize=False uses the raw covariates (singleton support — degenerate on continuous \(x\)). The discretisation is still needed even though Direct-X-X has no robustness term: it is what pools units so the free-π LP is well-posed.

3 · The in-sample problem (primal: raw factual reward)

With unit weights \(\hat w_i\equiv 1\), the IPW value of \(\pi\) is just the average observed factual reward \(V(\pi)=\frac1n\sum_i Y_i\,\pi_{T_i}(x_i)\). Direct-X-X maximises it directly — there is no inner worst case over any uncertainty set, because there is no uncertainty set:

\[ \boxed{\;\pi^\star \;=\; \arg\max_{\pi\in\Pi}\ \frac1n\sum_{i=1}^{n} Y_i\,\pi_{T_i}(x_i)\;} \]

with the feasible policy set

\[ \Pi:\quad \pi_k(x_i)\ge 0,\qquad \sum_{k}\pi_k(x_i)=1\ \ \forall i,\qquad \underbrace{\tfrac1n\sum_{i}\pi_k(x_i)\le\mathrm{cap}_k\ \ \forall k}_{\textbf{capped version only}}, \]

(plus the tie constraints). Because the objective is already linear in \(\pi\) with the weights fixed at 1, this is a plain primal LP — no dualisation is needed (unlike R-O / R-OW, where the inner \(\min_W\) is dualised). Equivalently, this is Direct IPW with \(\hat w_i\to 1\), or R-O / R-OW evaluated with a point-mass uncertainty set fixed at the (un-reweighted) sample.

4 · How it is solved — a direct LP with unit weights

Direct-X-X is IPW with the weights pinned to one, so it is solved as a direct LP — no dualisation. The three steps below are the entire recipe.

Step 1 — the objective is already linear in \(\pi\). Setting \(\hat w_i\equiv 1\) (no propensity correction) leaves the IPW value as the plain average factual reward, which is linear in the policy:

\[ V(\pi)\;=\;\frac1n\sum_{i=1}^{n} \hat w_i\,Y_i\,\pi_{T_i}(x_i)\;\Big|_{\hat w_i\equiv 1} \;=\;\frac1n\sum_{i=1}^{n} Y_i\,\pi_{T_i}(x_i). \]

Step 2 — maximise it directly under the policy constraints. There is no inner worst case to take, so we optimise \(V(\pi)\) straight over the feasible set: the per-unit simplex, the per-cell tie, and the (capped) capacity constraint:

\[ \begin{aligned} \max_{\pi}\ \ &\frac1n\sum_{i=1}^{n} Y_i\,\pi_{T_i}(x_i)\\[2pt] \text{s.t.}\ \ &\textstyle\sum_k \pi_k(x_i)=1,\quad \pi_k(x_i)\in[0,1],\quad \pi \text{ tied on each cell}; &&\text{(simplex + tie)}\\[2pt] &\textstyle\frac1n\sum_i \pi_k(x_i)\le \mathrm{cap}_k\quad\forall k. &&\textbf{(capacity — capped only)} \end{aligned} \]

Step 3 — solve the LP with Gurobi. The problem above is a plain linear program in the single variable block \(\pi\), handed directly to Gurobi. Because the factual reward is binary, \(Y_i\in\{0,1\}\), the objective coefficients take only two values and many units tie: the LP is typically degenerate / has alternate optima, so the optimal value \(V(\pi^\star)\) is unique but the maximiser is often not. Gurobi simply returns one optimal vertex \(\pi^\star\) among the alternate optima.

How it is used. The solve returns the on-support policy \(\pi^\star\) (K×n); off-support deployment is then handled by the Shapley / KNN extension (extensions/).

5 · What is actually solved (the LP)

The files build exactly the LP below. The only variables are the policy values \(\pi_k(x_i)\) — there are no dual / multiplier variables, because there is no inner minimisation to dualise.

\[ \max_{\pi}\ \ \frac1n\sum_{i=1}^{n} Y_i\,\pi_{T_i}(x_i) \]

subject to

\[ \begin{aligned} &\textstyle\sum_k \pi_k(x_i)=1,\quad \pi_k(x_i)\in[0,1],\quad \pi \text{ tied on each cell}; &&\text{(valid policy)}\\[2pt] &\textstyle\frac1n\sum_i \pi_k(x_i)\le \mathrm{cap}_k\quad\forall k. &&\textbf{(capacity — capped only)} \end{aligned} \]
variablemeaning
\(\pi_k(x_i)\in[0,1]\)the policy probability of arm \(k\) at unit \(i\) — the only decision variable; columns sum to 1 and are tied across same-cell units

There is no dual certificate to report: with weights fixed at 1 the problem is a single linear maximisation, so the saved result holds only \(\pi^\star\), its usage, the objective and the solver status — no \(\mu,\nu,\beta,\gamma,\theta\). Ported exactly from srpo.multiarm.solve_direct_opt_multiarm (= solve_direct_ipw_multiarm with \(\hat w\equiv1\)).

6 · Capped vs. Uncapped — the only difference

  • Capped/direct_x_x_capped.py — adds \(\frac1n\sum_i\pi_k(x_i)\le\mathrm{cap}_k\) (requires cap).
  • Uncapped/direct_x_x_uncapped.py — drops it (no cap argument); any arm may be assigned to any fraction.

7 · Direct-X-X vs the robust methods

Same value-maximisation skeleton, same discretisation and capacity — but Direct-X-X omits the propensity reweighting AND every robustness device. Consequences: no \(\hat w_i\), no odds box, no Wasserstein ball, and therefore no dual multipliers at all. Because it does not even correct for observed-\(x\) overlap, it is biased toward frequently-assigned / often-successful arms and is expected to be the weakest method. It is the trust-the-data reference against which Direct IPW (adds \(\hat w\)), R-O (adds the odds box) and R-OW (adds the Wasserstein balance) are measured — Direct-X-X equals IPW exactly when all weights happen to be 1.

8 · Arguments that shape the problem

argumenteffect
discretize (bool)discretisation switch: snap to grid (via support.py) and tie per cell, or use raw \(x\) (singleton support).
mesh (int)grid levels per coordinate when discretize=True (e.g. 6 ⇒ 6×6 cells in 2-D).
cap (capped only)per-arm capacity \(\mathrm{cap}_k\); the constraint \(\frac1n\sum_i\pi_k(x_i)\le\mathrm{cap}_k\) is enforced.

Outputs: the optimal on-support policy \(\pi^\star\) (K×n), its realised per-arm usage, the naive (\(\hat w\equiv1\)) objective, and the solver status — persisted per results/SAVING.md. Off-support deployment (extensions/) is a separate step.
