Oracle

A reference ceiling, not a deployable method (formerly srpo.multiarm.solve_oracle_capacity). Files: Capped/oracle_capped.py, Uncapped/oracle_uncapped.py.

One sentence. Given a value matrix \(V\in\mathbb R^{n\times K}\), the Oracle returns the best policy on the (discretised) support under capacity — the fair upper bound on what any method could achieve.

1 · Inputs

symbolmeaning
\(x_i\)covariates of unit \(i=1,\dots,n\); arms \(k=0,\dots,K-1\)
\(V_{ik}=\)values[i,k]value of assigning arm \(k\) to unit \(i\). Pass \(V=Y^{\text{pot}}\) (per-unit potential outcomes ⇒ clairvoyant Full-info ceiling) or \(V=\mu_k(X_i)\) (true means ⇒ deployable Best-true-means ceiling).
\(\mathrm{cap}_k\)per-arm capacity (capped version only)
Why this does not break the no-true-propensities rule. The Oracle is a benchmark, never deployed as a policy. It is therefore allowed to use ground-truth value information (\(Y^{\text{pot}}\) or \(\mu\)). The no-true-propensities rule forbids learned methods from weighting with \(e_{\text{true}}\); the Oracle is not a learned method — it only bounds them.

2 · The problem

With \(\pi_k(x)\in[0,1]\), \(\sum_k\pi_k(x)=1\), tied on each support cell (same discretize/mesh discretisation as the learned methods, so the ceiling is on the same support):

\[ \max_{\pi}\ \frac1n\sum_{i=1}^{n}\sum_{k=0}^{K-1}\pi_k(x_i)\,V_{ik} \qquad\text{s.t.}\qquad \sum_k\pi_k(x_i)=1,\ \ \pi\ge 0,\ \ \pi\ \text{tied per cell},\ \ \underbrace{\tfrac1n\textstyle\sum_i\pi_k(x_i)\le\mathrm{cap}_k}_{\textbf{capped only}}. \]

A plain LP (no robustness, no weights, no duals). With no capacity it reduces to the per-cell argmax of the average value; with capacity it optimally rations the scarce arms across cells.

3 · How it is solved — a direct assignment LP

Because the Oracle has full value access, there is no adversary and nothing to dualise: the problem of section 2 is solved as written, as a single transportation-style assignment LP.

Step 1 — the objective is already linear in \(\pi\). The value matrix \(V\) is known up front (\(V=Y^{\text{pot}}\) for the Full-info ceiling, or \(V=\mu\) for the Best-means ceiling), so the objective is a plain linear function of the policy:
\[ \frac1n\sum_{i=1}^{n}\sum_{k=0}^{K-1}\pi_k(x_i)\,V_{ik}. \]
There is no inner \(\min_W\) over a worst-case re-weighting — \(V\) plays the role that the (uncertain) IPW value plays in the robust methods, but here it is fixed data, not an adversary's choice.
Step 2 — maximise it directly under the policy constraints. We maximise the linear objective subject only to the policy structure — the per-unit simplex, the per-cell tie, and (when capped) the per-arm capacity:
\[ \max_{\pi}\ \frac1n\sum_{i=1}^{n}\sum_{k=0}^{K-1}\pi_k(x_i)\,V_{ik} \quad\text{s.t.}\quad \sum_k\pi_k(x_i)=1,\ \ \pi\ge 0,\ \ \pi\ \text{tied per cell},\ \ \underbrace{\tfrac1n\textstyle\sum_i\pi_k(x_i)\le\mathrm{cap}_k}_{\textbf{capped only}}. \]
This is a transportation-style assignment LP: it transports a unit (cell) mass onto the \(K\) arms so as to maximise total value, with the capacity rows acting as the supply limits on each arm.
Step 3 — solve. The LP is handed to Gurobi. With no capacity the rows decouple and the LP collapses to the closed form of the per-cell \(\arg\max\) of the average value — each cell goes all-in on its highest-value arm; capacity is what couples the cells and forces the LP to ration scarce arms.

How it is used. The Oracle is a reference ceiling: its policy and value are saved as benchmarks (the fair upper bound any method could reach on the same support) and are never deployed.

4 · Capped vs. Uncapped

  • Capped/oracle_capped.py — adds \(\frac1n\sum_i\pi_k(x_i)\le\mathrm{cap}_k\) (the fair ceiling under the same capacity the methods face). Requires cap.
  • Uncapped/oracle_uncapped.py — no capacity: each cell goes all-in on its best-value arm (the unconstrained ideal; with \(V=\mu\) this is the "best arm, no cap" map).
