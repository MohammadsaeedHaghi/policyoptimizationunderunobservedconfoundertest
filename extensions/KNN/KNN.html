KNN off-support extension

Inverse-distance k-nearest-neighbour deployment of an on-support policy to new covariates — the simpler alternative to the Shapley operator. This page states exactly what the file in this folder computes: KNN/knn.py (extend_with_knn and extend_with_knn_multiarm). There is no solver and no optimisation problem.

One sentence. A method learns a policy \(\hat\pi\) only on its (discretised) support; to deploy it at a new covariate \(x\), KNN returns the inverse-distance weighted average of \(\hat\pi\) over the \(k\) nearest support points, per arm, renormalised to the simplex. Unlike Shapley it is a plain local average — not a Lipschitz envelope — and it needs no Gurobi.

1 · Inputs

The extension does no statistical preprocessing; it consumes the output of a method's on-support solve plus the points at which a policy is wanted:

Note what is absent versus Shapley: there is no min–max operator and no \(A_{jk}(x)\) matrix — KNN only ever forms a convex combination of nearby support values.

2 · The operator (one arm)

Fix one arm. At a test point \(x\), let \(\mathcal N_k(x)\) be the index set of the \(k\) nearest support points (Euclidean), and let \(d_j=\lVert x-x_j\rVert\). The KNN extension is the inverse-distance weighted average

\[ \boxed{\;\hat\pi(x)\;=\;\sum_{j\in\mathcal N_k(x)} w_j\,\hat\pi(x_j)\;}\qquad w_j=\frac{1}{d_j+\epsilon},\qquad \sum_{j\in\mathcal N_k(x)} w_j=1, \]

where the weights are normalised over the chosen neighbours and the result is clipped to \([0,1]\). Closer support points get larger weight; \(\epsilon\) keeps \(w_j\) finite at \(d_j=0\). The neighbour count is clamped, \(k_{\mathrm{eff}}=\min(k,\,n_s)\), so one can never request more neighbours than support points exist.

3 · How it is computed — numbered steps

The \(K\)-arm deployment extend_with_knn_multiarm(X_test, X_train, pi_train, k=…) \(\to(K,n_{\mathrm{test}})\) runs the steps below. There is no optimisation/Gurobi anywhere.

Step 1 — extract_support (same cell-collapse as Shapley). For each arm, collapse \((\)X_train\(,\hat\pi)\) to unique covariate cells: round the covariates and take, per distinct cell, the mean of \(\hat\pi\) over its matching rows. This yields the support \(\{x_j\}_{j=1}^{n_s}\) with one value \(\hat\pi(x_j)\) each:
\[ (x_j,\ \hat\pi(x_j))\;=\;\Big(x_j,\ \operatorname{mean}\{\hat\pi(x_i):\ \text{round}(x_i)=x_j\}\Big). \]
For a discretised free-\(\pi\) method (already tied per cell) this mean is a no-op. The routine is shared with the Shapley extension, so both deploy from the identical support.
Step 2 — per arm, k-NN inverse-distance average. For each arm independently, find the \(k_{\mathrm{eff}}=\min(k,n_s)\) nearest support points to each test row, form the inverse-distance weights, normalise them per test point, take the weighted average of the support values, and clip to \([0,1]\):
\[ d_j=\lVert x-x_j\rVert,\qquad w_j=\frac{1/(d_j+\epsilon)}{\sum_{\ell\in\mathcal N_k(x)} 1/(d_\ell+\epsilon)},\qquad \hat\pi_{\mathrm{arm}}(x)=\operatorname{clip}_{[0,1]}\!\Big(\textstyle\sum_{j\in\mathcal N_k(x)} w_j\,\hat\pi(x_j)\Big). \]
Step 3 — renormalise the \(K\) arm values to the simplex. Stacking the \(K\) arms gives a column per test point; each column is projected onto the probability simplex (uniform fallback if a column sums to \(\approx 0\)):
\[ \pi_k(x)\;=\;\frac{\big[\hat\pi_k(x)\big]_{+}}{\sum_{\ell=0}^{K-1}\big[\hat\pi_\ell(x)\big]_{+}}\quad\forall k, \qquad\text{so}\quad \pi_k(x)\ge0,\ \ \sum_{k=0}^{K-1}\pi_k(x)=1. \]
The output is the deployable policy \(\big(\pi_k(x)\big)\in[0,1]^{K\times n_{\mathrm{test}}}\).

4 · How it is used

A method's solve returns the on-support policy \(\hat\pi\) (\(K\times n\)); to score or plot it anywhere off the support, call

\[ \texttt{extend\_with\_knn\_multiarm}(X_{\text{test}},\,X_{\text{train}},\,\hat\pi,\ k)\ \longrightarrow\ (K,\ n_{\text{test}}). \]

The single-arm primitive extend_with_knn(X_test, support_X, support_pi, k=…) returns an \((m,)\) vector and is what the multi-arm wrapper calls per arm in Step 2.

5 · KNN vs Shapley

Both extensions deploy the same support (Step 1 is shared) and both renormalise the \(K\) arms to the simplex (Step 3). They differ only in the interior operator and only off the support:

operatorinverse-distance average \(\sum_j w_j\hat\pi(x_j)\)Lipschitz min–max \(\min_k\max_j A_{jk}(x)\)

On the support the two extensions agree — KNN's nearest neighbour is the point itself (distance \(0\), dominant weight) and Shapley is exact by construction. They diverge only off-support: KNN smooths over neighbours, whereas Shapley returns the Lipschitz envelope. Comparing the two isolates how much the deployment rule (smooth vs Lipschitz) matters; the on-support policy being deployed is identical.

Output: the deployable \(K\)-arm policy \(\pi^\star(x)\) (\(K\times n_{\text{test}}\)) at the requested covariates. This is a pure deployment step — no objective, no duals, no Gurobi.
