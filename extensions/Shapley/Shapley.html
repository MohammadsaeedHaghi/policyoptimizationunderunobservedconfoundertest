Shapley off-support extension

A closed-form deployment operator (no solver) that takes a method's on-support policy \(\hat\pi\) — defined only on the discrete support points the LP was actually solved on — and extends it to new covariates \(x\). It is the production path of extensions/Shapley/shapley.py (ported from srpo.extension.{shapley,multiarm}, PDF/closed-form variant; the optional Gurobi "LP" variant is omitted).

One sentence. Given the values \(\hat\pi(x_j)\) a method assigned at its support points \(x_j\), the Shapley extension returns at every new \(x\) the tightest 1-Lipschitz interpolant consistent with those values — a min–max of pairwise distance-weighted averages — arm-by-arm, then renormalised to the simplex. There is no optimisation and no Gurobi: it is a closed-form scalar operator that is exact at the support.

1 · What it is (and what it is not)

A method (e.g. R-O, R-OW) returns a policy \(\pi\) of shape \((K\times n)\) defined only on the \(n\) (discretised) support covariates, together with the array of those support covariates support_X. The Shapley extension is the operator that deploys that policy to a held-out test set or a dense grid for plotting. It does not re-solve anything: unlike the methods in methods/, there is no uncertainty set, no dual, and no solver call here — only a closed-form evaluation.

2 · The operator (one arm)

Fix one arm and write \(\hat\pi(x_j)\) for its on-support values. For a query \(x\) with distances \(d_j=\lVert x-x_j\rVert\) define the pairwise distance-weighted average

\[ A_{jk}(x)\;=\;\frac{d_k\,\hat\pi(x_j)\;+\;d_j\,\hat\pi(x_k)}{d_j+d_k},\qquad A_{kk}(x)\;=\;\hat\pi(x_k), \]

and take the min–max over support indices:

\[ \boxed{\;\pi^{S}(x)\;=\;\min_{k}\ \max_{j}\ A_{jk}(x)\;} \]

This is the tightest 1-Lipschitz interpolant consistent with the support values \(\hat\pi(x_j)\) (PDF Lemma 1). It is exact at the support: if \(x=x_\ell\) for some support point then \(d_\ell=0\) and the operator returns the stored value \(\hat\pi(x_\ell)\) — the code takes a fast path that returns \(\hat\pi(x_{\arg\min_j d_j})\) whenever any \(d_j\le 0\).

3 · How it is computed (steps)

The extension is the three steps below. They contain no optimisation / no Gurobi — every step is a direct array computation.

Step 1 — extract_support: collapse duplicate cells. Round the training covariates and group identical covariate cells; the support value for a cell is the mean of \(\pi\) over the rows in that cell,
\[ \hat\pi(x_j)\;=\;\operatorname{mean}\{\,\pi_i \;:\; x_i \text{ lies in cell } j\,\}, \]
yielding the unique support \((\texttt{support\_X},\ \texttt{support\_pi})\). For a discretised free-\(\pi\) method the policy is already tied per cell, so this mean is a no-op; it is applied per arm.
Step 2 — evaluate \(\pi^{S}(x)\) at each test \(x\), per arm. For every query \(x\) compute the distances \(d_j=\lVert x-x_j\rVert\), form the matrix \(A_{jk}(x)\) with its diagonal set to \(A_{kk}=\hat\pi(x_k)\), and return
\[ \pi^{S}(x)\;=\;\min_{k}\ \max_{j}\ A_{jk}(x). \]
Each of the \(K\) arms is a separate scalar extension — \(K\) independent calls of the one-arm operator of section 2. An exact support match short-circuits to the stored value.
Step 3 — renormalise to the simplex. The \(K\) arms are extended independently, so their values at a given \(x\) need not sum to one. Clip to \([0,\infty)\) and renormalise each test point's \(K\) values onto the simplex,
\[ \pi_k^{\mathrm{deploy}}(x)\;=\;\frac{\big[\pi_k^{S}(x)\big]_+}{\sum_{k'}\big[\pi_{k'}^{S}(x)\big]_+}, \qquad \sum_{k}\pi_k^{\mathrm{deploy}}(x)=1, \]
with a uniform fallback \(1/K\) where a column sums to \(\approx 0\). At the support points \(\pi^{S}\) is exact, so the renormalisation is a no-op there.

4 · How it is used

A method returns \((\pi\ (K\times n),\ \texttt{support\_X})\); calling

\[ \texttt{extend\_with\_shapley\_multiarm}(X_{\text{test}},\ \texttt{support\_X},\ \pi)\ \longrightarrow\ \big(K,\ n_{\text{test}}\big) \]

returns the deployed policy on the test \(X\) (or a dense grid for plotting). The second positional argument is named \(X_{\text{train}}\) in the signature (as in the API table below); it receives the policy's covariate array — here the returned support_X — which the function collapses to unique cells internally via extract_support (so both raw and already-collapsed inputs are accepted). Internally it then runs Step 1 (extract_support) and Step 2 (extend_with_shapley) per arm, stacks, and applies Step 3 (_normalise). The public API is:

Summary: a deployment-only operator. Given a method's on-support policy and its support covariates, Shapley returns the tightest 1-Lipschitz interpolant per arm, renormalised to the simplex, exact at the support — closed form, no solver. Companion extension: nearest-neighbour (extensions/KNN).
