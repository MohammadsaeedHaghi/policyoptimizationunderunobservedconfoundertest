If you change anything in the codebase (a solver's signature, a constraint's
form, a default value, a new variant, a moved file, a class rename …), you
must also update **every HTML file in the repo that talks about that code**.

The HTMLs that exist:

- `code/README.html` — the top-level multi-tab report (problem, method tabs,
  experiments, …).
- `code/rw_implementation/README.html` — folder-level RW writeup.
- `code/kallus_implementation/README.html` — folder-level Kallus writeup.
- (Future per-folder READMEs as the project grows.)

**Why:** the user has explicitly said the HTMLs are the project's
documentation of record — they must stay aligned with the implementation.
A solver change that's not reflected in the HTML creates a future-trap
("the docs say X, the code does Y").

**How to apply.**

For any change:

1. Identify which HTML files describe the changed piece (use grep across
   `**/*.html`).
2. Update the formula, signature, code snippet, or behaviour description in
   every match.
3. Verify the parse remains clean (balanced tags, no broken `<code>` snippets).
4. Re-render anchor links if any IDs moved.

For new files / functions / classes:

1. Add them to the relevant HTML — usually the method tab in the top-level
   `README.html` and the per-folder README.

For deletions / moves:

1. Strip the obsolete description.
2. Update file path references that point at the old location.
3. Update import-shim documentation if a backward-compat shim was added.

When in doubt, grep for the function/class name across `**/*.html` and the
folder paths involved, and patch each match.

**GOTCHA — LaTeX inside `build_html.py` f-strings (learned 2026-06-08).** The HTML is generated by
`experiments/discrete/build_html.py`, where most card bodies are Python **f-strings** (`f'''…'''`). MathJax 3 is
configured (inline `\(…\)`/`$…$`, display `\[…\]`/`$$…$$`), so to add real equations you write LaTeX — but a
NON-raw f-string mangles backslash commands via Python escape processing: `\theta`→TAB, `\underbrace`→`\u…`
(SyntaxError/crash), `\frac`/`\big`→form-feed/backspace, `\alpha`/`\approx`→bell. FIX: make the function's
return a **raw f-string `rf'''…'''`** (keeps backslashes literal AND still interpolates `{var}`). Braces still
need doubling for literals: `{{`/`}}` → `{`/`}`, so e.g. `\mathrm{{Uniform}}`, `e^{{\gamma/2}}`, `\{{3,4,5\}}`.
`_contibin_shared_cards()` is `rf'''` for exactly this reason; conti2d/other cards are plain `f'''` (no LaTeX) —
if you add LaTeX there, switch them to `rf'''` too. Validate after: build runs clean, `$` count even, div
balance, then it renders on tab-activation (`typeset()` fires on subtab switch).
